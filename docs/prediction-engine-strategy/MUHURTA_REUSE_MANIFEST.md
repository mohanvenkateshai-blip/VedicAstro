# Native Muhūrta donor audit and reuse manifest

## Audit boundary

This is a read-only reuse assessment of the standalone donor at `/Users/ganesha/Projects/04-UX-Practice/Panchang/panchanga_muhurtha` against VedicAstro. It does not certify the donor's astrological accuracy. The native chart route must call CVCE only; the existing `/muhurta` iframe remains the migration fallback.

Decision vocabulary:

- **PORT** — reuse the behavior or consume the already-superior CVCE equivalent, with normal contract tests.
- **VALIDATE** — potentially useful, but it needs source reconciliation and calculation fixtures before product use.
- **QUARANTINE** — research input only; weights, claims, or provenance are too weak for a live verdict.
- **REJECT** — do not copy; VedicAstro already has a safer canonical implementation or the donor approach violates an architectural invariant.

“Maturity” below is relative engineering maturity, not measured predictive accuracy. No donor score or VedicAstro rule score is an empirically calibrated probability.

Acceptance rule for any future donor validation import:

1. Retain row-level blinded ratings, rubric version, candidate output hash, case definition, expert pseudonym, timestamps and consent basis.
2. Make aggregate metrics reproducible from those rows; store the exact analysis code and treatment of missing ratings.
3. Separate calculation agreement, textual-source fidelity, clarity/usefulness and real-world outcome accuracy. None is a substitute for another.
4. Verify independence and prevent simulated/generated records from being represented as human expert evidence.
5. Keep retrospective/expert judgment distinct from sealed prospective outcome evaluation.

## Smallest next three implementation slices

These are dependency-ordered and deliberately smaller than a wholesale Finder port.

1. **Canonical Panchanga boundaries and Muhūrta-window contract.** Extend CVCE to return exact limb start/end times, sunrise/sunset, avoid windows and a cited 30-slot/special-window model. Add boundary, DST, polar-condition and cross-engine fixtures. Render it in the existing native preview without scoring.
2. **Versioned starter activity profiles with evidence traces.** Implement three narrowly defined activity types as typed, source-bound constraints in research/shadow mode. Every rule emits an ID, interval, support/block status, exception, provenance and configuration version. No donor weight is promoted without an ablation/evaluation record.
3. **Bounded server-side Finder with Muhūrta Lagna.** Scan a capped date/time range using only canonical CVCE calculations and the typed starter profiles. Return deterministic candidates, exact local intervals, hard blockers, counterfactual alternatives and full traces. Feed those facts to PVE for precise, activity-specific language; do not reuse the donor's monolithic score or browser astronomy.

## Native parity rule

The current native `/chart/muhurta` preview is a safe first slice, not parity. Parity may be claimed only after the three slices above pass calculation fixtures, source/provenance gates, PVE comprehension tests and prospective evaluation appropriate to the claim. The standalone iframe remains unchanged until that evidence exists.
